# Life Radio 中央化改造：总控与分工

日期：2026-07-30，状态更新至 2026-07-31

## 最小目标

先完成一个可证明可靠的闭环：

1. PC 与 Android 只采集本机事实。
2. 两类客户端通过 HTTPS 上传到同一个中央服务。
3. 中央服务是唯一长期存储，不再把收到的数据转发给其他客户端。
4. Web UI 与 AI 只从中央服务读取。
5. 即使断网、进程退出、回执丢失或重复发送，也不丢事件、不重复存储、不串设备。

第一阶段只覆盖：

- PC ActivityWatch 应用、网站与 AFK 原始事件；
- Android 应用使用事件；
- Android `location.observation`；
- 现有确定性用量、位置与 AI 摘要。

不在第一阶段同时处理云平台选型、历史 JSON 全量迁移、远程命令队列和完整新 UI。

## 架构冻结

```text
PC 采集器 ─┐
           ├─ HTTPS /v1/events/batches ─> Central SQLite
Android ───┘                                ├─ Web UI
                                            └─ AI 只读上下文
```

- 新路径不发现其他 PC，不广播，不建立每个 peer 的账本。
- Tailscale、`/push`、`origin_device`、`relay:` 和强制同步到全部 PC 仅属于旧兼容路径。
- 稳定 `device_id` 由安装实例生成；hostname、显示名、IP、AW bucket 都不是身份。
- 客户端必须先写本地 outbox，只有中央回执中的 `confirmed_event_ids` 才能推进送达状态。
- 同一批次重试复用 `batch_id`；同一 `batch_id` 不同内容返回冲突。
- `location.observation` 不可变；允许更新的 ActivityWatch 持续事件必须使用更高 `revision`，且时长不得倒退。

- `contracts/life-radio-api-v1.yaml`
- `contracts/central-delivery-v1.md`
- `contracts/fixtures/central-desktop-batch-v1.json`
- `contracts/fixtures/central-desktop-ack-v1.json`

## 任务所有权

### 总管理任务

负责：

- 冻结架构、契约和验收标准；
- 划分任务并处理跨端冲突；
- 审查子代理结果；
- 运行全量回归；
- 决定何时允许旧链路切换到中央链路。

总管理任务不直接与手机端任务同时修改 `mobile-app`。

### 手机端任务

独占负责：

- Android 原生采集；
- Room 事件队列与送达状态；
- 固定中央 HTTPS 地址和设备令牌；
- 批量上传、逐事件 ACK、离线重试；
- Android 构建、模拟器和真机测试。

手机端不得自行修改中央服务实现。影响协议的变更必须先进入 `contracts/`。

### 契约代理

负责：

- OpenAPI、fixtures 和中央送达语义；
- 保证 PC、Android 和中央服务使用同一字段含义；
- 检查契约与实际回执漂移。

### 中央服务代理

负责：

- 独立 `central/` 服务；
- SQLite 事务、设备令牌绑定、批次幂等、事件去重与 revision；
- 后续的查询、AI 只读接口和中央 Web UI；
- 不引入 AW、托盘、Tailscale 或 P2P 代码。

### PC 客户端代理

负责：

- 安装级稳定设备身份；
- SQLite outbox；
- ActivityWatch 和本地自定义事件入队；
- 固定中央地址上传、重试与状态；
- 保持托盘、实时小窗和本地采集可用。

PC 客户端只上传本机产生的数据，不上传本地历史库中来自手机或其他 PC 的数据。
