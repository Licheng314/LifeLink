# 2026-07-30 Android 位置采样优化测试

## 测试版本

- Android 调试包：`v3.0 (21)`
- 分享文件名：`life-radio-v3.0-21-debug.apk`
- 目标：用一天真实手机数据确认零间隔重复、延迟回放和长时间空档分别来自哪里。

## 本版修改

- 仍以五分钟为目标间隔，但从平衡精度改为高精度位置请求，并关闭应用主动设置的批量回调延迟。
- 回调不再只读取 `lastLocation`；Android 一次返回多条新鲜位置时，会按实际定位时间逐条处理。
- 本地详情页、同步事件时间和 PC 排序统一使用 Android `location_time`，不再使用应用收到回调的时间代替实际定位时间。
- 同一秒、同一五位小数坐标和同一定位来源会生成稳定的同一个 event ID；系统重复回放时直接忽略，不增加重复位置。
- 拒绝十分钟以上的旧缓存位置，以及超过当前时间两分钟的异常位置。
- 手机位置详情页新增“与上一条间隔”，可直接检查五分钟节奏和空档长度。
- 加速度计仍只做旁路诊断，不参与位置筛选。批量回放时只有最新位置带完整加速度窗口，旧位置显示传感器证据不可用，避免重复计算同一窗口。

## 明日验收

1. 查看“今日位置采集详情”，多数连续记录应接近五分钟，且不应再大量出现 `0 秒` 间隔。
2. 若仍出现几十分钟或数小时空档，记录空档起止时间，并核对该时段常驻通知是否消失、手机是否重启或系统是否限制后台。
3. PC 对照同一天 `location.observation`：手机本机数量与各 PC 的不同 event ID 数应一致。
4. 查看 `observed_at - location_time`：正常应很小；接近十分钟表示 Android 延迟回放，超过十分钟的缓存不会进入新数据。
5. 观察一天电量变化。高精度五分钟请求比 v2.9 更耗电；若数据节奏明显改善，再决定是否保留或回调到平衡精度。

## 兼容性

- 事件类型仍为 `location.observation`，接口仍走既有 `/push`，未新增 PC 接口。
- 旧 `location.sample` / `location.stay`、旧观察数据和每台 PC 的独立送达账本保持兼容。
- 时间与稳定 ID 规则已同步更新到 `contracts/location-semantic-events-v1.md`、OpenAPI 和 fixture。
