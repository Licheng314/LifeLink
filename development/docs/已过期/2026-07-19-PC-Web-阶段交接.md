# 2026-07-19 PC/Web 阶段交接

## 已完成的能力

- **统一事件长期库**：PC 按稳定设备标识、事件类别和本地业务日保存事件；接收端按全局 `event_id` 去重，AW 持续事件和活动位置段可覆盖更新。
- **v1 与兼容层**：`/v1/events/batches` 和 `/v1/health` 对应共享 v1 契约；旧 Android `/push` 继续映射入统一库。
- **Tailscale 多 PC 中继**：本机将长期库事件广播给在线、可访问的非 Android/iOS PC。每个远端有独立送达账本；普通同步只发送未确认事件，强制同步重放本机当前业务日数据，但不清空账本。接收端去重保障强制重放安全。
- **ActivityWatch**：本机仅回读当前及前一个本地业务日，跨日时间点可配置；window、web、afk 原始事实均长期保存。
- **设备与使用看板**：设备同步页和应用使用页按设备展示；PC 在线时长来自非 AFK，手机在线时长来自应用使用总时长。
- **网站与黑名单派生**：Chrome 不直接参与网站排行。网址观察（包括零时长心跳）标记其后的 Chrome 前台区间，直到下一网址标记或 Chrome 区间结束；黑名单网站据此统计。
- **位置段**：PC 接收并展示 `location.sample` / `location.stay`，支持同 ID 的活动段更新与定稿；位置页面包含设备来源、最近位置、位置段和 AI 摘要。
- **AI 上下文**：`/api/ai-context/usage.md` 与 `location.md` 生成可供 OpenClaw 读取的确定性 Markdown；`index.json` 用于发现入口，`README.md` 说明口径和排障。

## 当前运行口径

1. “今天”及按日分档遵循本地时区与设置中的跨日时间点，不是 UTC 零点。
2. AI 摘要是读取时根据长期库生成的派生结果，并不独立采集。同步完成后，下一次摘要读取即可反映新数据。
3. 手机不是 PC 中继的发送目标；它仍按自己的现有流程向可访问 PC 上传。
4. 地址和位置段可作为个人模式数据，仅应经受控 Tailnet 路由传输。

- OpenClaw 的定时触发和对用户的通知策略尚未在本项目中配置；它只需按 AI 读取说明访问运行中的 PC 服务。
