# 2026-07-19 Android 阶段交接

> 2026-07-30 更新：当前位置采样测试包已升级为 `v3.0 (21)`，时间、去重和高精度请求规则见 [`2026-07-30-Android位置采样优化测试.md`](2026-07-30-Android位置采样优化测试.md)。

## 已完成并验证

- Android 调试包已更新为 `v2.9 (20)`；已完成代码与契约更新，等待真实手机安装后复测。
- 应用使用系统 `UsageStatsManager` 作为手机使用数据的主采集来源；ActivityWatch 保留为用户显式开启的备用采集，不删除旧逻辑。
- 手机到每台 PC 的送达记录按稳定节点 ID 分开维护。一台 PC 成功接收不会阻止另一台 PC 接收同一事件。
- Android 的 PC 服务默认端口已与 `pc-dashboard/config.json` 统一为 `8090`。
- Tailscale Management API Key 不再写入源码；用户需在应用设置中填写。缺少 Key 只影响节点发现和同步，不会删除本地采集数据。

## 位置数据语义

- `v2.9` 固定每 5 分钟请求一次平衡精度位置；每次成功且精度不超过 500 米的定位都生成一个独立 `location.observation`，不再在手机端按 150 米聚类。
- 本地 `location_samples` 与待同步 `data_events` 在同一 Room 事务中使用同一个观察 ID 写入。只要详情页出现一条新数据，同步队列就有对应的独立事件。
- 每个观察包含接受时间、Android 定位时间、经纬度、精度、定位来源、模拟位置标记和可用的地址语义；`duration=0`。
- 每个观察还包含从上一条有效定位（首条则从服务启动）到当前定位之间的 `motion_window`：加速度计是否可用、传感器采样数、阈值上穿次数、阈值和峰值。
- 加速度传感器只作为旁路诊断信息。它不参与定位筛选、不改变五分钟间隔，也不会阻止任何有效定位同步。
- 升级时若偏好设置中仍有旧版活动位置段，应用会按最后实际观测时间定稿一次；之后不再创建新的手机端位置段。

## 手机界面

- 数据页位置卡显示：`X 个位置 [本机 Y 条数据]`。新版本稳定运行后两者应同步增长；旧版遗留段可能使当天升级时短暂不完全相等。
- “查看今日位置采集详情”显示独立同步数量、兼容的旧版位置段，以及逐条位置数据。
- 每条位置数据直接显示对应加速度窗口的触发次数、传感器采样数、峰值和阈值，便于在真实手机上评估敏感度。

## 共享同步约定

- Android 继续走既有 `/push` 兼容链路，但新增 `location.observation` 事件语义；共享字段以 `contracts/life-radio-api-v1.yaml` 和 `contracts/fixtures/sync-batch-v1.json` 为准。
- 每个观察使用不同 event ID 且 `ready_to_sync=true`；每台目标 PC 的送达账本独立判断，因此任一 PC 先接收都不会减少其他 PC 的数据。
- PC 按 event ID 仅去重真正的重传，完整保存所有不同 ID 的观察。`/api/locations` 返回原始 `observations`，并在 PC 查询层按 150 米派生 `segments`。
- 旧 `location.sample` / `location.stay` 与活动段覆盖规则保持可读、可同步。

## 发布与运行注意

- Android 一次只能有一个 `VpnService`。真实手机上 Tailscale 与 Clash 同时启用可能互相断开；Windows 上可同时运行不代表 Android 也可以。
- 每次分享 APK 时必须使用带版本号的新文件名，例如 `life-radio-v2.9-20-debug.apk`。不要将新包继续以 `app-debug.apk` 同名发送给 QQ，QQ 可能按文件名保留旧文件。
- 当前调试产物目录为 `mobile-app/app/build/outputs/apk/debug/`；`app-debug.apk` 仅是 Gradle 内部默认产物，不是可分享的最终命名。
