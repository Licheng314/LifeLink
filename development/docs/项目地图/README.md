# Life Link 项目地图

本目录提供两种并列的可视化入口：

- Obsidian 全量项目地图：[`Life Link 项目地图.canvas`](Life%20Link%20项目地图.canvas)。
- 面向沟通的现役架构总览：[`Life Link 架构总览.html`](Life%20Link%20架构总览.html)，其可编辑源文件为 [`Life Link 架构总览.architecture.json`](Life%20Link%20架构总览.architecture.json)。
- 面向新用户的基础连接拓扑：[`Life Link 基础连接拓扑.html`](Life%20Link%20基础连接拓扑.html)，其可编辑源文件为 [`Life Link 基础连接拓扑.architecture.json`](Life%20Link%20基础连接拓扑.architecture.json)。

架构总览由 Archify 生成，聚焦当前数据流、本地体验与 AI 被动读取链路；它不替代 Canvas 地图，也不引入运行时依赖。

项目地图是从现役文档、代码和验证证据整理出的派生视图，不是新的事实权威。发生冲突时仍按以下顺序判断：

```text
共享契约 > 项目总控中的已决策事项 > 模块 README > 日期交接记录 > 项目地图
```

## 地图表达

- 主连线只表示当前冻结架构中的主要链路：契约约束、事件上传与 ACK、中央读取、PC 本地代理和集成验证。
- 模块节点面积近似表示源码规模，依据源码文件数和源码行数人工分档；它不代表代码质量或业务重要性。
- 每个模块节点内列出最相关的现役文档。跨模块设计文档可以同时关联多个模块。
- 颜色固定表示模块类别：中央紫色、PC 蓝色、Android 绿色、契约橙色、测试灰色、治理与文档黄色。
- 状态文字区分代码状态、自动化测试和真实设备验收，不把三者合并为一个“完成”。

## AI 更新约定

总控代理在以下时点检查并更新项目地图：

- 跨模块方案获批；
- 执行代理完成交付；
- 自动化验收或真实设备验收完成；
- 模块边界、共享契约或主要数据链路变化；
- 开发阶段结束并使用 `neat-freak` 做知识收尾。

更新前必须读取 `development/docs/README.md`、`development/docs/项目总控.md`、受影响契约、模块 README、实际代码差异与验证证据。只更新有证据的状态；尚未验收的内容写成“开发中”或“待验收”。

每次更新至少检查：

1. 主拓扑是否仍符合冻结架构；
2. 模块规模是否发生足以改变视觉分档的变化；
3. 当前执行项、风险和验收状态是否准确；
4. 模块关联文档是否新增、退役或改变归属；
5. 地图中的核验日期是否同步更新。

第一版不使用后台监视器、社区插件、Bases 或独立状态数据库。地图由 AI 在项目状态节点更新，保持简单且可审计。
