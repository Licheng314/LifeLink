## 冻结产品口径

1. Android 权限请求使用系统统一流程，允许用户选择全部照片或所选照片。实现必须识别无权限、部分权限与全部权限；权限收窄造成的“不可见”不等于用户取消同步。
2. 手机照片页浏览当前可访问的全部历史照片。顶部用大标题独立展示“今日照片”，下方“过往照片”按业务日倒序分组，日期之间有明确分隔。
3. 照片的唯一权威时间是 `captured_at`（实际拍摄或截图时间）。`business_date` 根据中央 `Asia/Shanghai + day_start_hour` 派生，不改写精确时刻。无可靠拍摄时间时可回退 MediaStore 加入时间，并保存 `time_source=added`。`added_at` 仅可作为 Android 内部增量发现信息。
4. 勾选状态表示本设备的期望同步集合。只有用户显式切换才产生变化。底部确认栏仅在有变化时出现，分开显示“新增 N 张，移除 M 张”，不使用净变化数。
5. 照片二进制是不可变资源。逻辑身份必须包含来源 `device_id`；即使文件哈希相同，不同设备的同步记录也不能互相删除。
6. 中央删除不影响手机原图。来源设备必须看到“中央副本已删除/同步已失效”，只有再次勾选并确认才重新上传。
7. 中央 WebUI 照片页默认显示全部日期，按业务日分组；可切换“仅当前业务日”。显示来源设备，采用限量初始加载和继续加载。
8. 本阶段 AI 不获得图片内容。每次成功确认同步由中央幂等生成一条普通重要度汇总事件，包含新增数、其中当前业务日照片数、移除数与明确业务日。同步重试不得重复生成事件。

## 技术边界

- 照片内容不进入 `events.payload_json`、不进入 SQLite BLOB、不使用 Base64 JSON 上传。
- SQLite 保存元数据、同步版本和最小删除记录；文件位于唯一中央数据目录下的 `media/photos/`。
- 复用已注册设备 Token。Android 只能上传、删除和查看自己来源的同步状态；中央管理 WebUI 可汇总读取和删除。
- 上传必须是有严格大小上限的二进制请求，验证 MIME、文件签名、长度和 SHA-256，且可幂等重试。
- Android 不把“当前不可见”解释为取消选择。取消同步必须来自显式 UI 操作。
- 中央必须使用分页或游标读取；WebUI 不一次加载全部图片内容。

## 接口协作约定

契约/中央执行单元先冻结并实现最小完整接口。命名可由执行代理根据现有 v1 风格确定，但必须涵盖：

1. 本设备照片状态的分页列表，含活跃/中央已删除状态。
2. 单照片二进制幂等上传，包含客户端稳定照片 ID、`captured_at`、`time_source`、MIME、尺寸、字节数和 SHA-256。
3. 单照片幂等删除；设备只能删自己来源的记录。
4. 中央管理的全部照片元数据分页列表、图片内容读取和删除。
5. 一次用户确认操作必须携带稳定 `sync_id`；中央在所有单项处理结束后以该 `sync_id` 幂等投影一条同步汇总事件。允许响应显式列出部分失败，但事件只统计真正成功变更。

## 验收标准

- 功能未启用或无权限时不读取相册，不影响现有采集与事件上传。
- Android 14 允许全部和所选照片权限，部分权限下明确标记可见范围可能不完整。
- 手机与 WebUI 均按业务日分组；手机当日区显著突出，WebUI 默认全部日期且可切换仅当日。
- 初始限量加载，继续加载不重复、不丢失勾选状态。
- 底部栏仅在有明确变化时显示，分开统计新增和移除。
- 权限收窄、原图被移动或暂时无法解码时，不会自动产生中央删除。
- 同一上传和删除重试幂等；不同来源设备的逻辑记录互不影响。
- 中央删除后手机可见同步失效状态，重新上传需要用户再次确认。
- 同步汇总事件数量准确、包含明确业务日，且重试不重复。AI 不获得图片内容。
- 旧库启动时幂等新增 schema，不重写旧事件。
- 至少覆盖无权限、部分权限、重复上传、重复删除、跨设备隔离、超限文件、非图片伪装、分页与同步汇总去重测试。

- 契约/中央执行单元：契约 fixture，存储、HTTP、鉴权、文件验证、幂等和汇总事件专项测试。
- Android 执行单元：权限状态、MediaStore 投影、业务日分组、差异计算、客户端协议和 Compose 可构建验证。

- 总控：检查契约一致性、实际差异，运行中央全量与 Android 关键回归；真机权限和大相册须单独标记待验收。
