# Life Link 代理执行规范

更新时间：2026-08-08

本规范用于降低多代理开发的上下文消耗、重复测试和范围扩张。项目事实仍以共享契约、项目总控、模块 README、代码和测试为准。

## 一、任务分级

| 等级 | 典型范围 | 默认执行方式 |
| --- | --- | --- |
| 小型 | 1～2 个文件；文字、样式或局部逻辑；不改变契约、权限和存储 | 当前代理直接执行；需要代理时使用 Terra-low |
| 中型 | 边界明确的跨文件或单模块算法修改 | Terra-medium 执行代理；总控验收 |
| 大型 | 架构、迁移、联网、身份权限、长期数据或多模块语义变化 | Sol 规划/审查；拆分后优先由 Terra 执行 |
| 机械 | 文档同步、搜索替换、补简单测试 | Terra-low，限制文件范围 |

风险高于文件数量。即使只改一个文件，只要涉及删除数据、认证、同步确认或时间语义，也按大型或高风险任务处理。

## 二、子代理上下文

默认禁止把完整长对话复制给执行代理。

推荐顺序：

1. 总控依据 `development/docs/协作/任务模板.md` 形成独立任务单。
2. 子代理使用无历史上下文启动。
3. 子代理读取 `development/docs/README.md`、项目总控、任务单、对应契约和模块 README。
4. 只有文档无法表达的近期选择，才额外提供最少几轮对话。

任务提示必须直接列出允许修改的文件和明确不做事项，避免执行代理自行遍历全部历史文档。

## 三、模型选择

- 默认执行：`gpt-5.6-terra`。
- 机械任务、文档和简单测试：低推理。
- 明确的多文件实现和普通算法：中等推理。
- Sol 仅在复杂架构、数据安全、高价值故障定位或独立高风险验收中使用。
- 不因为“更强更保险”而默认让执行和验收同时使用 Sol。
- 若当前代理软件不支持这些模型名称，选择其可用模型中定位最接近的“平衡型/轻量型”，并在报告中注明。

## 四、测试所有权

为避免重复消耗：

- 执行代理：运行新功能专项测试和最相关模块测试。
- 验收代理：阅读实际差异，验证关键反例，并运行一次必要的全量回归。
- 若执行代理已经运行全量测试，验收代理根据风险决定是否只复跑关键测试；数据、权限、同步等高风险变更仍可独立全量验证。
- 测试输出使用安静模式或摘要，只保留数量、通过/失败和失败堆栈。

## 五、跨软件协作

Codex、WorkBuddy 和其他代理之间不假定能够读取彼此的内部对话。统一通过项目文件协作：

```text
总控形成任务单
  → 执行代理读取任务单并修改代码
  → 执行代理在任务单末尾或独立反馈中记录证据
  → 总控检查实际代码和测试
  → 通过 / 需要小修 / 退回
```

用户只需要向外部代理说明：

> 请从 `development/docs/README.md` 开始阅读，并执行指定任务单；完成后按代理执行规范反馈。

## 六、交付格式

执行代理使用精简的固定格式：

```text
完成目标：
修改文件：
口径/契约变化：
专项测试：
未完成或风险：
需要真实设备验证：
```

总控对用户默认只报告：

```text
结论：通过 / 需要小修 / 退回
你需要知道：最多三点
你需要决定：仅在确实需要选择时出现
```

给执行代理的返工提示仍应包含文件、原因、修改要求和验收标准，不能为了对用户简短而让执行任务含糊。

## 七、定期审查

每个开发阶段结束时检查：

- 是否仍在维护重复的新旧实现；
- 是否存在可以退役的 legacy/P2P 路径；
- 是否有同一事实在多个文档重复维护；
- 是否有执行代理继承了不必要的完整上下文；
- 是否重复运行并输出了同一批全量测试。

发现上述问题时，先登记为简化任务，不在当前功能中顺手扩大范围。
