# 任务规划：中央权威 WebUI 迁移（2026-09-04）

## 用户目标

将当前 PC Dashboard 中面向个人全局数据和设置的 WebUI 迁移到中央服务。用户在中央主机打开 `http://127.0.0.1:8092` 时，页面直接读取中央 SQLite 的实时权威视图，不经过 PC 客户端的只读代理、磁盘缓存或 outbox 快照。PC 的采集、outbox、同步、小窗及所有本机控制不在迁移范围。

第一阶段只服务中央主机本地浏览器；远程浏览器登录、账号、会话和权限模型是独立后续任务，不能通过公开 8092 临时实现。

## 架构决定

```text
本机浏览器 ── loopback / CSRF ──> 中央权威 WebUI :8092 ──> 中央 SQLite / 派生视图

PC 客户端 ──> 原生采集 + outbox + 上传 + 用时小窗
```

- 8092 继续只绑定 `127.0.0.1`，使用现有 Host、Origin、CSRF 与 no-store 边界；不直接把设备 Token 或 AI Token 交给浏览器。
- “直接”指数据从中央权威存储/派生视图读取，不保留 PC 本地读取缓存，也不把 PC 当作中间数据源；不是要求浏览器绕过 8092 的安全后端直接访问 SQLite。
- 页面动态数据全部 `Cache-Control: no-store`；允许浏览器缓存带版本号的静态 CSS/JS，但不缓存个人数据响应。
- 已有中央管理功能（网络配置、Tailscale 检测、设备邀请码、AI MCP 下载）并入完整中央 WebUI 的“管理”页签，而非保留第二个孤立页面。
- 中央位置页使用与 PC 相同的公共天地图 Key；Key 由中央部署配置提供并由中央瓦片代理使用，浏览器请求不携带 Key。地图不可用时位置摘要与活动状态继续可用。
- 初期应优先复用中央现有读写语义，不复制算法。若现有 HTTP handler 内嵌了业务逻辑，先抽为中央内部 service/facade，再由数据 API 和 WebUI 共用；不能让 WebUI 自行重算业务日、AFK、位置、健康或 AI 标记。

## 页面迁移范围

| 当前 PC Dashboard 功能 | 中央 WebUI 归属 | 迁移方式 |
| --- | --- | --- |
| 业务日周历、事件时间线、心愿、报告、触发器 | 是 | 直接使用中央 calendar、timeline、wishes、settings/trigger 语义；先迁移只读，再迁移写入。 |
| 应用/网站用量、黑名单 | 是 | 中央 usage 与 blacklist 规则为权威来源；不保留 PC 只读缓存回退。 |
| 位置轨迹、活动状态、健康/步数 | 是 | 中央 locations、health、shared settings 直接返回；地图底图代理另列处理。 |
| 设备名册、名称、逻辑删除、共享跨日设置 | 是 | 使用中央 device/settings 写入；移除 PC 本地代理层。 |
| AI reader 状态、访问记录、预览、清理标记、连接包 | 是 | 已归中央管理页；合并进统一页面，不重复发包入口。 |
| PC outbox、立即同步、采集开关、浏览器插件、登录启动、用时小窗、实时本机前台快照 | 否 | 保留在 PC 客户端的本机诊断/控制入口；它们不是全局中央数据。 |
| 地图瓦片代理与天地图 Key | 暂不直接迁移 | 中央位置页先保留数据和无地图降级；另行决定将公共 Key/瓦片代理部署到中央，不能读取 PC 私有配置。 |
| 媒体工具、打开本机文件夹 | 暂不迁移 | 先确认其真实归属和服务器部署安全，再单独立项。 |

## 实施阶段

## 当前进度（2026-09-05）

- 已保留中央 loopback 安全边界和中央真实读取接口；此前为中央临时重绘的页面壳、简化渲染脚本和自定义样式不再作为迁移基础。
- 已把 PC Dashboard 的原始 HTML、样式、页面脚本、Leaflet 和品牌资源复制为中央端静态基线。此时的标准是先保持原版 DOM、CSS 和页面结构，不以“相似重做”替代移植。
- 原 PC 脚本仍含 PC 专属接口、缓存和本机控制，不能直接作为中央运行时。下一步是由中央同源适配层逐页满足可迁移的只读请求，再逐项迁移写入；PC 专属行为须显式禁用或替换为说明。
- 已完成首批同源适配：周历、时间线、用量、位置、健康、设置、设备、心愿/触发器读取、背景摘要、AI Reader 和黑名单规则直接读取中央；共享设置、设备改名/删除、黑名单 CRUD 与触发器 CRUD 已使用既有中央存储写入，并受 8092 的 Host、Origin 与 CSRF 边界保护。
- 已消除已发现的 PC 专属展示残留：侧栏健康状态改为中央服务自身状态；登录 Windows 启动项、立即上传到中央不再在中央页提供可误导的动作；AI 状态显示中央实际访问记录而不错误声称能检查另一台 AI 主机的进程。两个 AI 配对入口均下载由中央生成的 MCP 包。
- 原版图表与图标运行库已转为中央本地静态资源，避免为了复制 PC 外观而允许管理页加载外站脚本。中央现以与 PC 相同的公共天地图 Key 通过服务器端瓦片代理供图，Key 不进入浏览器 URL。心愿每日评估/完结、报告设置、AI Reader 管理细项和异常状态收口仍待逐项完成。
- 已修正中央响应策略与原版渲染方式之间的冲突：继续禁止内联脚本，仅允许原版页面受控使用的内联样式。此前同一冲突会同时造成心愿新增按钮退化、时间线图标/标签失去颜色以及应用用量柱状图消失。现已在实际浏览器中逐项与 PC 原版比对，并增加响应策略和核心视觉资源同源回归测试；后续迁移验收不能只检查接口与文件存在，还必须检查浏览器计算样式和代表性页面截图。
- AI 配对只保留事件时间线中的单一入口：下载包、查看 Skill 与查看/复制 MCP JSON 都在同一张 AI 卡片中完成；MCP JSON 只展示与压缩包一致的本地占位模板，不生成第二份配对材料。中央管理页按“设备管理、网络配置、设备配对、统计设置”排列，删除重复的 AI 配对和服务端自身连接状态。中央页不再尝试检测远端 AI 主机进程；有效 AI 在最近 30 分钟有 MCP 读取访问时，亮绿灯并显示“AI X 分钟前访问过”。
- 中央 WebUI 的当前业务日时间线继续按 30 秒、仅可见当前页刷新；页面以 `ETag` 条件请求中央实时投影，未变化返回无正文 `304`。PC 用时小窗保留独立的固定业务日查询、本机最后成功副本和 30 秒刷新，不依赖浏览器是否打开，也不与浏览器建立数据转发通道。
- PC 客户端自身的登录后启动不迁入中央 WebUI：它只能由该 Windows PC 的托盘菜单控制。菜单使用系统勾选状态；切换仅创建或移除本客户端的当前用户启动项，并给出本机通知。
- 中央 HTTPS WebUI 已完成用户可见验收后，PC `sync_server` 不再提供 `/`、`/dashboard.html` 或旧静态资源；旧 `dashboard.html`、`web/` 和页面测试已删除。8090 保留给采集、上传、浏览器插件兼容和用时小窗的固定业务日时间线读取。
- 中央托盘是数据服务子进程的唯一受控生命周期所有者：常规重启必须经托盘的“重启服务器”完成，由私有 shutdown capability 优雅停止后再启动。排障时不得只结束监听 8091/8092 的子进程；这会使托盘误判为异常退出并进入退避重试。已按完整父子进程树完成一次恢复验证。
- 远程位置页的地图瓦片继续仅由中央代理获取，天地图 Key 不进入浏览器；公共 PNG 瓦片在已认证会话中可缓存 24 小时，个人页面/API 响应仍保持 `no-store`。

### 0. 基线与可删除清单

为每个 PC 页面列出：DOM/静态资源、`/api/*` 调用、中央对应资源、仅 PC 依赖、读写权限和验收样本。先补中央 API/facade 的缺口及测试，不复制页面后再发现数据不一致。

### 1. 中央页面骨架与只读真实数据

在 `central-server/management-web/` 建立完整导航、共享业务日周历和页面状态。先迁移时间线、用量、位置、健康、设备名册的只读显示；所有请求从中央进程返回，不使用 PC 地址、PC Token、PC 缓存或本机 fallback。旧 PC Dashboard 保持可用用于逐页对照。

### 2. 中央写入与 AI 管理合并

迁移心愿、每日评估、触发器、报告、黑名单、设备命名/删除、跨日设置及 AI Reader 管理。每个写入保持当前幂等、权限、错误与审计语义；UI 的本机 CSRF 不替代中央资源的业务授权检查。

### 3. 中央地图与体验收口

决定地图瓦片方案并实现无地图降级；完成响应式布局、错误状态、空数据、历史业务日和中央重启后的刷新。此阶段仍不公开 8092。

### 4. PC WebUI 下线（已完成）

中央 WebUI 已完成用户可见验收后，PC `dashboard.html`、静态页面资源和对应页面测试已移除，`sync_server` 不再提供这些路径。PC 不再自动打开完整 Dashboard；采集、outbox、同步和小窗功能保留。后续仅继续清理不再被小窗或运行时调用的旧只读代理端点与缓存实现。

## 验收标准

1. 断开或关闭 PC 客户端后，中央本机 WebUI 仍能显示中央已确认的时间线、用量、位置、健康、设备与 AI 状态。
2. 页面数据与中央 SQLite/现有受保护 API 的同一业务日结果一致；不出现 PC 缓存时间戳、离线 fallback 或第二份权威状态。
3. 新上传的 PC/Android 事实在中央确认后刷新中央页面即可出现；不依赖 PC Dashboard 的同步或缓存刷新。
4. 心愿、设备、黑名单、共享设置和 AI 管理写入后，中央重启及另一台设备读取均保持一致。
5. 浏览器响应不含设备 Token、AI Token、配对材料、SQLite 路径或原始敏感数据；8092 非 loopback Host、跨源写入和公开反向代理继续被拒绝。
6. 历史业务日、空数据、中央暂不可用、地图不可用、无 PC 在线、重复写入和中央重启均有明确且不误导的页面行为。
7. PC Dashboard 删除前，以自动化与人工对照证明所有已迁移页面可用；仅 PC 本机功能仍有清晰入口。

## 风险与不做事项

- 这是大型跨模块迁移，不在一次改动中复制并删除 PC Dashboard。
- 不新增远程浏览器认证、账号系统、OAuth、公开管理端或多用户权限；这些需要独立安全设计。
- 不让 WebUI 直接读 SQLite，不绕过中央业务层，不把 Token 写进 JavaScript。
- 不把“无缓存”误做成高频无节制轮询；数据实时性由中央确认后刷新、条件请求和用户可见刷新控制保证。

## 已批准的远程浏览器会话边界

PC 客户端下线本地 Dashboard 前，远程浏览器访问采用一次性启动码换取短期 Cookie 会话，而不是公开 `8092` 或把设备 Token 交给浏览器：

1. 已配对 PC 使用自己的设备凭据向中央 HTTPS 数据端口申请一次性启动码；中央只在已验证 `public_endpoint` 存在时签发。
2. PC 打开已验证 HTTPS 地址，启动码仅放在 URL fragment 中；fragment 不会进入 HTTP 请求、反向代理日志或 Referer。最小公开引导页以 POST 换取 `Secure`、`HttpOnly`、`SameSite=Strict` 会话 Cookie 后立即清除 fragment。
3. 中央数据端口只对持有该 Cookie 的浏览器提供完整页面与 `/api/*` 适配层；每个会话另有 CSRF 值，所有写请求必须同时通过 Cookie 和 CSRF 校验。会话、启动码仅驻留中央进程内存，短时过期，中央重启立即失效。
4. 数据端口内部以 loopback 调用既有 `8092` 管理适配层，并保留其 Host/Origin/CSRF 边界；远程浏览器绝不直连 `8092`，也看不到其内部 CSRF 或任何中央 Token。关闭服务器等非页面管理操作不经远程代理。
5. 静态资源可公开读取但不含个人数据；页面、动态接口与任何错误响应继续 `Cache-Control: no-store`。公网入口必须仍是 HTTPS，HTTP、重定向、未配置端点、过期或已领取启动码一律拒绝。

PC 客户端托盘和用时小窗的“打开 WebUI”只允许打开上述 HTTPS 会话地址；不得因中央同机、端点暂不可用或升级中的接口失败而回退打开 `8092`。`8092` 仅由中央服务端托盘在中央主机本机打开。
