# 中央管理 WebUI 与 Windows 托盘职责拆分

状态：**代码完成，待 Windows 与真实网络验收**
批准日期：2026-09-04
风险等级：中等偏高（涉及中央服务进程生命周期、本机管理接口和配对入口迁移）

## 一、目标

本阶段先完成中央服务的管理界面与 Windows 平台外壳拆分：

1. 新增一个由中央服务提供的本机管理 WebUI，承担基础项目设置。
2. 将设备配对、AI 配对和网络配置从 Windows 托盘迁入管理 WebUI。
3. 将 Windows 托盘收缩为平台专用的进程外壳，只负责打开管理 WebUI、重启中央服务和关闭中央服务。
4. 让中央核心逻辑不再依赖托盘、Tkinter 或桌面会话，为下一阶段适配 Linux/Docker 留出清晰边界。
5. 从 Windows 托盘外壳中一并移除 Tkinter：改用现有 Windows 原生托盘消息循环，并使用原生消息框或托盘通知反馈必要错误，使 Tkinter 不再是中央服务的安装条件。

Linux 服务器和 Docker 部署不在本阶段实现，放入下一阶段。

## 二、最终职责边界

```text
中央服务核心
├─ 对外数据 API（现有 8091 或中央配置中的实际端口）
├─ 本机管理 WebUI（固定监听 127.0.0.1:8092）
├─ 数据库、鉴权、配对签发、网络配置和业务逻辑
└─ 不依赖 Tkinter、系统托盘或 Windows 登录启动

Windows 平台外壳
├─ 启动并观察中央服务进程
├─ Windows 登录后启动登记
├─ Windows 原生托盘消息循环和必要通知
└─ 托盘菜单：打开 WebUI / 重启服务器 / 关闭服务器
```

中央服务核心拥有设置和配对事实；Windows 托盘不得再保存或复制这些业务配置。

## 三、中央管理 WebUI

### 3.1 访问边界

- 管理 WebUI 固定绑定 `127.0.0.1:8092`，仅允许服务器所在机器访问；本阶段不增加动态管理端口或端口选择设置。
- 管理 WebUI 不通过公网入口、Tailscale Serve 或中央对外数据端口暴露。
- 本阶段不增加远程管理、用户账号或多管理员体系。
- 修改配置的请求必须具备基本的本机来源保护，不能仅凭“监听回环地址”忽略 Host、Origin 和跨站请求风险。
- 管理 WebUI 与现有 PC 数据展示 WebUI 是两个不同入口；本阶段不迁移事件时间线、应用使用、位置、健康、心愿等数据展示页面。

### 3.2 页面只提供三组核心功能

#### A. 设备配对

- 显示当前已配对设备的简要状态。
- 复用现有 `LR1.` 注册协议生成一次性设备配对码。
- 明确显示有效期，并提供复制操作。
- 已存在设备时仍允许用户主动生成新的配对码，但不在每次启动时重复生成。
- 生成失败时给出原因，不修改已有设备和凭据。

#### B. AI 配对

- 延续用户可理解的名称“生成 AI 配对包”。
- 复用现有 Reader 身份、权限和配对包格式，不另建第二套 AI 身份协议。
- 成功后给出压缩包位置，并提示“将压缩包发送给 AI 来完成连接”。
- 若当前 Windows 实现仍需本机 PC 服务协助装包，可以暂时复用；PC 服务不可用时必须明确提示，不得生成看似成功但内容不完整的包。
- 将“彻底解除 AI 配对包对 PC 服务的依赖”留给后续独立任务，不夹带在本次界面迁移中。

#### C. 网络配置

- 页面首先只读显示中央数据服务的实际本机目标，例如 `127.0.0.1:8091`；该目标供 Caddy、Tailscale Serve 或 HTTPS 内网穿透转发。管理 WebUI 自身的 `127.0.0.1:8092` 不作为远程连接目标。
- 页面提供三种连接方式，最终都归一为一个“外部 HTTPS 地址”：
  1. **公网服务器/域名**：用户完成域名解析、HTTPS 和反向代理后，填写 `https://life.example.com`；自定义公网端口允许写成 `https://life.example.com:8443`。默认 HTTPS 端口 443 不要求用户填写。
  2. **Tailscale**：提示或检测 Tailscale 状态，将 Tailscale Serve 的 HTTPS 地址登记为外部地址；现阶段允许复用 Windows 已有辅助流程，也始终允许手动粘贴已经获得的地址。
  3. **HTTPS 内网穿透**：显示需要填写到花生壳或同类工具中的内网主机 `127.0.0.1` 和中央实际端口，再由用户粘贴服务商生成的 HTTPS 地址。
- 允许暂时跳过远程连接，但只标记为“尚未配置”；服务器本机仍可运行，远程设备和远程 PC 暂不可用，不另建永久性的“仅本机模式”。远程 AI MCP 经公网域名直连不在本任务实现。
- WebUI 不保存花生壳、Tailscale、域名服务商或 Caddy 的账号密码和管理 Token，只保存连接类型、最终 HTTPS `base_url`、验证状态和验证时间。
- 外部地址不得包含用户信息、查询参数、片段或配对 Token；允许域名和显式 HTTPS 端口，不接受普通公网 HTTP 作为正式连接地址。
- “验证连接”至少检查地址格式、TLS、Life Link 健康响应以及返回的稳定中央服务器身份，避免地址错误地指向另一项服务或另一套 Life Link。
- 新地址先作为候选值验证；验证或保存失败时保留原来的有效地址，不能用空值或失败结果覆盖。若受网络回环限制无法在服务器本机完成外部验证，应明确显示“待外部设备验证”，不得谎报成功。
- 验证成功后才将地址设为当前配对材料使用的外部地址。更换地址只改变传输入口，不得创建新的中央身份、设备身份或数据库。
- 首次安装时中央数据端口优先使用 8091；若首次发现端口冲突，可以选择并持久化其他可用端口。已有配置以后发生冲突时必须明确报错，不得静默换端口，因为 Caddy、Tailscale 或穿透映射仍指向旧端口。
- 花生壳、Tailscale、Caddy 等工具负责建立网络通道；Life Link 负责显示正确的本机转发目标、保存最终地址并验证它。Linux/Docker 下的工具安装与自动化仍属于下一阶段。

### 3.3 页面状态

- 首次启动或尚未完成必要配置时，自动打开 `http://127.0.0.1:8092`，并在一个页面内指出缺少的项目。
- 日常启动保持后台运行；用户从托盘选择“打开 WebUI”时再打开浏览器。
- 每项设置独立保存和独立报错，某一项失败不得阻止其他项目使用。
- 页面只展示必要的配置结果和错误，不扩展日志中心、数据库维护、备份恢复、运行指标等管理功能。

## 四、Windows 托盘

### 4.1 可见菜单必须只有三项

1. **打开 WebUI**：打开中央服务返回的本机管理地址。
2. **重启服务器**：有序停止中央核心进程，确认退出后重新启动；失败时给出明确提示。
3. **关闭服务器**：有序关闭中央核心进程并退出托盘外壳。

从托盘删除设备配对、AI 配对、网络配置、查看配对状态等业务入口。

### 4.2 平台职责

- 托盘只在 Windows 下启用。
- 托盘外壳负责判断由自己管理的中央进程是否仍在运行，并防止重复启动中央写进程。
- Windows 登录后启动仍由 Windows 外壳/首次初始化流程负责，并保持默认启用；它不作为第四个托盘菜单项。
- 开机启动登记必须指向正式的 Life Link 启动器，不能恢复 VBS、Python、终端或失效旧路径入口。
- 若 Windows 或安全软件阻止登录启动，应显示真实失败状态或指引用户前往系统设置处理，不能回报“设置成功”。
- 托盘不得承担中央数据库、配对签发、网络地址保存等业务职责。
- 托盘不得再创建隐藏的 Tkinter 根窗口，也不得依赖 `tkinter.messagebox`；必要提示使用 Windows 原生接口，持续监测使用独立计时或消息机制。

## 五、进程关系与失败处理

- 中央核心进程负责同时提供数据 API 和本机管理 WebUI；管理 WebUI 不是托盘进程临时托管的页面。
- Windows 外壳作为进程管理者启动中央核心，并使用明确的健康检查确认它已就绪。
- “重启服务器”必须避免同时存在两个中央写进程；旧进程未退出时不得直接拉起新进程。
- 中央启动失败时，托盘仍应保留可用的错误提示和重试能力；“打开 WebUI”应提示服务尚未就绪，而不是打开空白页。
- 若 8092 已由另一项程序占用，中央服务应明确报告管理端口冲突并停止管理入口初始化；若占用者是当前已运行的 Life Link 实例，则托盘应复用并打开该实例，不得另起第二套服务。
- 关闭操作应优先走受控退出，超时后才使用限定到已确认子进程的强制结束，不能按模糊进程名批量杀进程。
- 中央服务被外部意外终止时，托盘应能识别为异常停止；是否自动重启沿用现役策略，本任务不新增无限重启循环。

## 六、明确不做

- 不实现 Linux、Docker、systemd、无桌面服务器部署或跨平台安装包。
- 不把现有 PC 数据展示 WebUI 整体迁入中央服务。
- 不开放远程管理 WebUI。
- 不新增数据库表、配对协议、Reader 权限或设备身份格式。
- 不改变 Android/PC 上传、中央 ACK、历史数据和业务日语义。
- 不在本任务中调整 AI 在线状态判断或 MCP 定时访问制度。
- 不新增复杂后台、日志面板、资源监控、备份恢复等功能。

## 七、建议实施顺序

1. 从现有中央托盘代码中划出平台无关的设备配对、AI 配对和网络配置服务函数。
2. 在中央核心中新增只监听回环地址的管理 WebUI 和内部管理接口。
3. 实现三组页面功能，并保证保存失败时旧配置不变。
4. 将 Windows 托盘菜单收缩为三项，并让它只通过进程控制和管理 WebUI 地址工作。
5. 移除中央核心对托盘和 Windows 登录启动模块的导入依赖；同时从 Windows 外壳移除 Tkinter，用 Windows 原生消息循环、计时和提示接口替代现有隐藏根窗口、`after` 调度与 `messagebox`。
6. 更新首次启动流程：初始化 Windows 外壳和登录启动，必要时打开管理 WebUI 完成基础设置。
7. 删除首次安装流程中对 Tkinter 可用性的检查，保留实际需要的 Python 和构建工具检查。
8. 完成专项自动化和 Windows 真实运行验收后，再更新项目总控的“当前代码事实”。

## 八、允许修改范围

- `central-server/` 内的中央核心、Windows 托盘外壳、首次启动流程、管理 WebUI 静态资源及专项测试。
- `development/docs/` 中的现役索引、中央模块说明和本任务交付记录。
- 如现有 AI 配对包必须调用 PC 本机接口，本阶段只允许复用，不默认修改 `pc-dashboard/`；确需修改时先补充任务范围并再次确认。
- 不修改 Android、共享数据契约、长期库结构和用户历史数据。

## 九、验收标准

### 自动化验收

- 中央核心在不导入 Tkinter/托盘代码的情况下可以启动数据 API 和本机管理 WebUI。
- Windows 托盘进程也不导入 Tkinter；缺少 Tcl/Tk 的 Python 环境仍可启动中央服务和托盘。
- 管理 WebUI 固定监听 `127.0.0.1:8092`，非本机来源无法直接访问；端口被非 Life Link 程序占用时错误明确且不会误连。
- 设备配对码、AI 配对包和网络配置分别覆盖成功、失败与旧配置保留测试。
- 托盘菜单文本和命令严格为三项；重启不会产生双中央进程，关闭能够有序退出。
- 现有中央数据 API、上传、ACK、查询、设备身份和 AI Reader 回归不受影响。

### Windows 真实验收

- 首次启动能够启动中央服务，并在需要设置时打开 `http://127.0.0.1:8092`。
- 设备配对码可被现有 PC 或 Android 客户端领取。
- AI 配对包可被现有 AI 连接流程使用；依赖缺失时提示准确。
- 网络地址更新成功后，现有远程客户端仍可连接；失败输入不会破坏原地址。
- 托盘只显示三项，打开、重启、关闭均符合预期。
- 重新登录 Windows 后只出现一个带 Life Link 名称和图标的中央启动项，不再出现 VBS 残留或重复中央进程。

## 十、下一阶段

本任务完成并稳定后，另行设计 Linux/Docker 适配，重点处理：

- Linux 下无托盘、无 Tkinter 的直接启动方式；
- Docker 镜像、数据卷、环境变量和端口映射；
- 首次初始化在无桌面环境中的访问方式；
- Linux 的守护进程、自动重启和升级策略；
- AI 配对包在没有 Windows PC 服务时的独立生成能力。

下一阶段不得通过在 Linux 中模拟 Windows 托盘来复用本任务，而应直接运行中央核心和本机/受控管理入口。

公网域名下的远程 AI MCP 对接不属于本任务。现役 AI 配对包仍使用 loopback claim；其正式远程接入、鉴权和域名边界另行立项。

## 十二、2026-09-04 交付记录

- 中央核心新增固定回环管理服务与静态 WebUI，提供设备状态/邀请、AI 配对包转交、外部 HTTPS 地址验证保存和受控关闭。
- 管理写请求具备严格 Host、Origin 与 CSRF 保护；托盘关闭使用不返回给浏览器的进程级 Bearer 能力。管理响应不含设备凭据和中央只读凭据。
- 新外部地址先验证 TLS、中央健康响应、认证读取与稳定 `central_instance_id`，成功后原子保存；失败保留原配置。
- Windows 托盘改为原生消息循环，菜单严格为三项；异常退出按 2/5/10 秒最多重试三次，强制退出只限定其持有的子进程。
- 首次启动同时等待数据 API 与管理 WebUI，就绪后打开 8092；中央启动环境不再检查 Tkinter。
- 交互复核后补充：AI 打包、设备邀请和网络验证均在对应功能区立即显示处理中、成功或失败，并在处理中禁用按钮；空网络地址由浏览器直接提示。AI 打包成功会打开资源管理器、返回并展示完整 ZIP 路径和有效期，PC 的安全错误说明会传递给管理页。
- Tailscale 提供“自动检测”入口：只检测 CLI、登录与 DNS 状态，并把专用 8443 HTTPS 候选地址填入文本框；不创建或修改 Serve 规则，不验证，不保存或覆盖既有外部地址。用户确认转发后仍须点击“验证并保存”。
- 自动化：中央服务完整测试集 225 项、PC 客户端完整测试集 224 项（1 项按环境跳过）、跨中央/PC/Windows 启动入口的集成测试 10 项通过。原生 Windows 托盘窗口已完成创建并立即关闭的冒烟验证。自动化通过不等于人工托盘操作、真实公网网络或真实设备验收通过。
