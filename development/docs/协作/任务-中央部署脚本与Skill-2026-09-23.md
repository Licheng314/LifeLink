# 中央部署脚本与 Skill

- 用户目标：把反复手工执行的服务器更新缩成可检查的一条命令，再提供简短易读的对话入口。
- 风险等级：大型（线上切换和持久数据备份）；本任务只实现与无切换验证，不执行线上发布。
- 允许修改：`central-server/Dockerfile`、`central-server/maintenance/deploy_server.sh`、`central-server/deploy.local.example.json`、`central-server/README.md`、`development/tools/deploy-central.ps1`、`.codex/skills/life-link-central-deploy/SKILL.md` 以及必要的忽略规则和文档索引。
- 明确不做：不改 Android/PC 客户端，不迁移数据库，不自动提交现有工作区，不把密钥或生产配置纳入 Git，不在本任务切换线上容器。
- 数据与契约影响：不更改应用契约；执行发布时先独占停止中央服务，对完整持久卷打包，再启动新镜像。镜像失败后恢复旧镜像，不自动恢复数据库文件，避免覆盖升级期间的数据。
- 验收标准：本机 `-DryRun` 不连接服务器或推送；服务器 `--check` 不改动服务；脚本语法检查通过；未经提交的部署相关文件阻止正式发布；部署成功必须同时通过容器、回环 API、管理页和存在时的公网 HTTPS 检查。
- 测试分工：当前代理进行 PowerShell 解析、Skill 校验、Bash 语法、本机 dry-run 和服务器只读检查；真实发布需由后续明确请求触发，届时再验收切换和回退能力。
- 本次结果：本机 dry-run 与未提交文件阻断均通过；服务器 Bash 语法、`--check`、SSH Git 只读访问通过；新 Dockerfile 在服务器构建测试镜像成功，中央模块与 Pillow 导入通过。未运行 `--apply`、未切换服务。Skill 校验器因本机 Python 缺少 PyYAML 未能执行，已人工检查 frontmatter 和占位符。
