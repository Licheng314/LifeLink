# 设备编辑 WebUI 基础需求

状态：v1.9.0 契约、中央、PC 本地代理和 WebUI 设备卡改造均已完成代码与自动化，真实多设备改名、事件名称投影、旧 Token 失效和删除后重新绑定已于 2026-08-16 验收通过。本文保留为基础行为规范，不规定最终视觉排版。

## 1. 目标

把 PC WebUI 现有的“设备同步”页面改造成“设备管理”页面，让用户能够：

- 查看当前仍在使用的中央设备；
- 给设备设置中央自定义名称；
- 删除不再使用的设备，使其无法继续同步；
- 保留该设备已经上传的用量、位置、时间线和其他历史事实。

本页面不修改稳定 `device_id`，不物理删除历史数据，不提供设备合并、批量操作、恢复列表或 Android 管理入口。

后续稳定增补：设备管理页承载共享“跨日时间”设置。设置仍写入中央共享设置，不改变统计口径，只从“应用使用”迁移到更合适的设备级管理位置。设备管理属于客户端 WebUI，不签发设备邀请码；邀请码继续由中央主机的受控入口生成。

## 2. 数据口径

- `display_name`：当前应向用户展示的中央有效名称。
- `reported_name`：客户端最近上报的原始名称，例如电脑 hostname 或手机型号，只作为灰色辅助信息。
- `custom_name`：用户设置的中央名称。存在时，中央所有视图、AI 摘要和可解析的事件称呼都优先使用它。
- `is_current=true`：当前打开 WebUI 的 PC，允许重命名但不能删除。

设备上传的新原始名称不得覆盖 `custom_name`。

## 3. 现有页面改造

不新增独立页面、右侧管理面板或复杂设置中心，直接复用当前页面：

- 侧边栏“设备同步”改名为“设备管理”；
- 页面标题“多端同步”改名为“设备管理”；
- 页面说明同时表达设备管理和同步状态；
- 继续使用现有设备卡区域，保留中央连接状态、最近同步时间、今日同步数量和“立即上传”等已有信息；
- 内部 `data-page="sync"`、`page-sync`、`sync-device-cards` 等标识可以保留，避免为文字改名扩大代码变更。

当前页面实际由本机中央上传状态卡和其他设备同步状态卡组成。改造后应按稳定 `device_id` 把设备管理名册与同步快照合并，呈现为每台已注册设备的一张卡片；不能用设备名称关联数据。

每张设备卡至少显示：

1. 平台图标或“电脑 / 手机 / Web”文字；
2. 可原位编辑的当前名称 `display_name`；
3. 原始名称 `reported_name`，仅当它与当前名称不同时显示；
4. 最近同步时间；
5. 当前设备标记；
6. 卡片上的“删除”按钮。

当前设备的“删除”按钮应隐藏或禁用，不要让用户提交后才发现不能删除。

## 4. 重命名

- 不设置独立“重命名”按钮，也不打开弹窗；设备卡中的名称栏位本身可编辑，默认填入当前 `display_name`。
- 去除首尾空白后必须为 1～100 个字符。
- 不要求设备名称唯一。
- 用户修改内容后才启用名称栏旁的紧凑“保存”操作；按 Enter 等同保存，按 Esc 或取消编辑恢复原值。
- 输入过程中不得逐字发送请求。
- 保存成功后立即刷新设备列表，并刷新页面中已经加载的设备、用量、位置和时间线名称。
- 保存失败时名称栏恢复中央现值，并在卡片附近或统一 Toast 显示失败原因。
- 不提供“恢复默认名称”专用按钮；用户仍可手动输入原始名称。

请求：

```text
PATCH /api/device-management/{device_id}
Content-Type: application/json

{"display_name":"书房电脑"}
```

PC 本地代理会把它转换成中央 POST 兼容请求，浏览器不接触中央 Token。

## 5. 删除设备

界面统一使用“删除设备”这个名称，后台实际是逻辑停用：

- 撤销该设备凭据；
- 从当前设备管理列表移除；
- 停用明确绑定该设备的设备用量触发器；
- 不删除原始事件、批次、位置或历史时间线；
- 重新使用该设备时必须重新领取邀请码。

删除按钮直接放在对应设备卡上。由于现有卡片可能带有点击或选择行为，删除和名称编辑控件必须阻止点击事件冒泡，不能误触卡片的其他操作。

删除需要一次确认：

```text
删除“随身手机”？
删除后该设备将无法继续同步；历史数据会保留。重新使用时需要重新连接。
```

确认后请求：

```text
DELETE /api/device-management/{device_id}
```

成功返回 `204`。随后关闭确认状态并刷新所有设备相关视图。

## 6. 离线和错误

- `GET /api/device-management` 返回 `X-Life-Radio-Cache: stale` 时，面板显示“当前离线中”，并禁用重命名和删除。
- 保存失败时保留原名称，不做乐观覆盖。
- 删除失败时保留设备行，允许重试。
- `cannot_delete_current_device`：提示“不能删除当前正在使用的设备”。
- `device_not_found`：刷新列表，不重复显示已删除设备。
- `credential_source_not_mutable`：提示“中央凭据配置当前不支持设备删除”。
- `credential_cleanup_failed`：提示“设备已停用，但凭据清理未完成，请稍后重试”，不要宣称删除完整成功。
- 认证或网络错误沿用现有中文错误提示，不显示 Token、中央私有地址或技术堆栈。

## 7. 本地接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/device-management` | 读取未删除设备及当前设备标记 |
| PATCH | `/api/device-management/{device_id}` | 修改中央自定义名称 |
| DELETE | `/api/device-management/{device_id}` | 逻辑删除设备并撤销凭据 |
| GET / POST | `/api/settings` | 读取或修改共享跨日时间 |

`GET /api/device-management` 是卡片名册和名称、删除状态的权威来源。现有 `/api/devices?date=...` 仍用于补充某个时间窗口的同步状态与统计；两份数据如需合并，只能按稳定 `device_id` 关联，不能按 `display_name`、`reported_name` 或 hostname 关联。

## 8. 验收

1. 重命名手机后，再次上传仍显示自定义名称，不恢复手机型号。
2. 设备页、用量、位置、AI 摘要和新生成的事件使用同一中央名称。
3. 已有设备用量里程碑在读取时能够按新名称展示，不批量改写原始时间线行。
4. 删除后旧设备 Token 上传返回 401，中央重启后仍不能恢复。
5. 删除不减少该设备的原始事件和批次数量。
6. 删除当天已经产生的用量仍可进入当天统计；没有新事实的后续日期不再显示该设备。
7. 当前 PC 无法删除自身，另一台已注册设备可以删除它。
8. 侧边栏和页面标题显示“设备管理”，原有同步状态、立即上传和刷新能力仍可使用。
9. 名称在设备卡内直接编辑，不出现独立重命名弹窗；编辑和删除不会触发卡片的其他点击行为。
