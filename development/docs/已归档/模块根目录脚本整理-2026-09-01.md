# 模块根目录脚本整理

状态：2026-09-01 已完成，仅供事后调查。

## 目标与边界

- 精简中央服务和 PC 客户端根目录，只保留主要启动入口、正式启动器和现役运行源码。
- 将恢复/诊断 BAT 归入各模块 `maintenance/`，将启动器构建源码归入各模块 `launcher/`。
- 不重构现役 Python 包结构，不改变身份、同步、鉴权、端口或数据库语义，不触碰 `%USERPROFILE%/LifeLink` 权威运行数据。

## 实际处理

- 删除两个已无调用者的 `start_hidden.vbs`。
- 将源码目录中两份含凭据的旧 `config.json` 副本移入 Windows 回收站。
- 将 Git 跟踪的空 `central-server/central.sqlite3` 移入 Windows 回收站；其设备、事件和批次数均为 0，不是现役中央长期库。
- 更新维护入口、构建脚本、现役 README、项目总控和邀请契约中的路径引用。
- 启动器在 Python 安装目录不可枚举时跳过该候选位置，继续尝试其他显式或系统解释器。

## 同日跟进：服务端 BAT 闪退

- 根因不是中央服务崩溃，而是 BAT 被保存为 UTF-8、仅 LF 换行并直接包含中文；Windows `cmd.exe` 实际把多行拆成了 `'Life'`、乱码片段和残缺变量名等错误命令。
- `.gitattributes` 现强制 `*.bat` 与 `*.cmd` 使用 CRLF。6 个现役 BAT 统一为纯 ASCII + CRLF；主 BAT 只负责解析初始化脚本绝对路径、调用系统 Windows PowerShell、传递退出码并在失败时停留窗口。
- 当日曾临时加入“旧安装静默补齐初始化状态并直接复用”的兼容逻辑。该行为随后被 2026-09-02 的现役决定取代：每次手动运行服务端 BAT 都进入远程连接检查菜单，已有有效地址可默认保留；直接运行 EXE 和登录后启动仍保持静默。
- 新增批处理编码/桥接回归 2 项；当时中央首次运行与托盘相关测试 22 项通过。真实 `cmd.exe` 已验证 BAT 能连续运行，`127.0.0.1:8091/v1/health` 返回中央服务正常；后续交互行为以现役安装流程为准。
