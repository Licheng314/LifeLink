# 心愿与事件系统：WebUI 设计方案

状态：v1.13.1 现役 WebUI 规范；中央语义、基础页面、前端视觉与交互调整已于 2026-08-16 完成并验收通过

更新时间：2026-08-16

## 1. 页签变更

| 当前页签 | 调整 |
|----------|------|
| 旧时间线 | 删除，由中央事件时间线取代 |
| 同步 | 保留并升级为设备管理 |
| 应用使用 | 保留 |
| 位置轨迹 | 保留 |
| 自定义事件 | 删除；需要面向用户展示的事件统一进入事件时间线 |
| 健康信息 | 保留；统一承载睡眠与步数，不恢复独立睡眠页 |
| 小工具 | 保留 |
| 事件时间线 | 保留，作为心愿和重要系统事件的统一入口 |

不新增“触发器”页签。触发器只作为某条心愿编辑模板内的提醒设置；已有心愿允许修改、关闭或替换提醒。

PC WebUI 首期不增加往期心愿页面。中央仍保存自然到期的归档心愿，Android 已有往期入口；PC 后续需要时再单独设计，不影响本期当前心愿和事件时间线。

## 2. 心愿卡片区域（嵌入事件时间线页顶部）

### 2.1 行数规则

- 无心愿：第 1 行显示大号 "+" 按钮
- 1 条心愿：心愿占第 1 行，第 2 行保留小号 "+"
- 2 条心愿：心愿占第 1、2 行，第 3 行保留小号 "+"
- 3 条心愿：全部占满，不显示 "+"
- 全局上限 3 条，中央检查，前端提前禁用

### 2.2 单条卡片布局

```
┌──────────────────────────────────────────────────────────────────┐
│ 🎯 减少游戏时间                                      🔔   编辑 │
│                                                                    │
│ ○8/9  ○8/10  ○8/11  ○8/12  ○8/13  ○8/14  ○8/15                 │
└──────────────────────────────────────────────────────────────────┘
```

**第 1 行**：
- 左侧：心愿文字，大字号（如 20px bold），占主要空间
- 右侧：可选触发器图标 + 编辑按钮
  - 有已启用的心愿挂接 → 只显示统一提醒图标（🔔）
  - 无挂接 → 不显示；不展示"提醒激活中"等文字详情
  - 编辑按钮打开与创建共用的心愿模板，编辑文字和提醒；底部额外提供“删除心愿”
  - 旧“取消心愿”按钮不属于目标界面，现役界面使用编辑与永久删除

**第 2 行**：7 个 `[图标][日期]` 块，单行排列，每个可点击
- 图标 + 紧凑日期 "8/9" 格式
- 点击任一日期 → 弹出评估弹窗

### 2.3 日期状态与图标

| 状态 | 图标/外观 | 说明 |
|------|----------|------|
| 已完成 | 🟢 绿色实心圆 | `evaluation=completed` |
| 今日 | 🔵 蓝色实心圆 | 日期 = 当前业务日，未评估 |
| 未抵达 | 🔲 灰色方框（checkbox） | 日期晚于当前业务日 |
| 未完成 | 🔴 红色实心圆 | `evaluation=not_completed` |
| 待确认 | ⬛ 黑色方框（checkbox） | 日期早于当前业务日，未评估 |

### 2.4 评估弹窗

点击日期后弹出居中浮层：

```
┌──────────────────────┐
│  8/12 心愿是否完成？   │
│                      │
│  [已完成]  [未完成]    │
│                      │
│  （点击其他区域取消）   │
└──────────────────────┘
```

- 已完成 / 未完成：两个按钮，互斥选择
- 点击任一按钮后：PUT 评估结果 → 关闭弹窗 → 更新对应日期图标
- 点击浮层外部区域：关闭弹窗，不作任何修改
- 未来日期（未抵达）不弹出

### 2.5 Toast 通知

所有操作通过右上角 toast 提示结果，2.5 秒后自动消失：

| 操作 | 成功提示 | 失败提示 |
|------|---------|---------|
| 评估 | 已完成 ✓ / 未完成 ✗ | 评估失败 |
| 创建心愿 | 已创建 | 创建失败: [详情] |
| 设置提醒 | 提醒已设置 | 提醒设置失败 |
| 完结心愿 | 心愿已完结 | 完结失败 |
| 删除心愿 | 心愿已删除 | 删除失败 |

- 成功 toast：绿色背景
- 失败 toast：红色背景
- 操作成功后自动刷新心愿卡片和事件时间线

### 2.6 编辑与删除入口

- 点击卡片右侧“编辑”按钮，打开创建/编辑共用模板。
- 模板内“删除心愿”需要一次永久删除确认；确认后发送 DELETE，成功后刷新面板，心愿从列表移除。
- 当且仅当当前业务日已超过 `ends_on` 时，卡片显示带对号图标的“完结心愿”按钮。点击后，如果有未评估日期，弹窗按具体日期列出并阻止提交；全部已填时再询问是否确认完结。
- 离线状态下禁用编辑、删除与完结，统一提示“当前离线中”。
- 不提供“取消心愿”或未到期提前终止交互；“完结心愿”严格属于到期后归档。

## 3. 创建与编辑共用模板

### 3.1 入口

- 创建：事件时间线页的 "+" 按钮 → 打开空白模板
- 编辑：心愿卡片右侧“编辑”按钮 → 打开同一模板并回显文字、周期和提醒
- 创建模式允许选择 3 天/7 天；编辑模式回显该选项但灰置不可修改
- 两种模式都不显示或预览生效日期；创建完成后由心愿卡片展示中央返回的固定日期

### 3.2 页面布局

标题栏统一为 `设置心愿`。表单宽度 660px（约 1.5 倍标准浮层宽度），各元素圆角统一为 10-16px。

```
┌──────────────────────────────────────────────────┐
│  设置心愿                                  ✕ 关闭 │
├──────────────────────────────────────────────────┤
│                                                    │
│  心愿内容                                          │
│  ┌────────────────────────────────────────────┐   │
│  │ 减少游戏时间                                │   │
│  └────────────────────────────────────────────┘   │
│                                                    │
│  选择周期                                          │
│  ○ 三日  ● 七日                                   │
│  （编辑模式灰置，创建模式可选）                       │
│                                                    │
│  提醒触发器（单选）                                   │
│  ┌────────────────────────────────────────────┐   │
│  │ ┌ 黑名单使用过量提醒 ──────────────────┐   │   │
│  │ │               提醒时限 [60 分钟 ▼]    │   │   │
│  │ └──────────────────────────────────────┘   │   │
│  │ ┌ 设备使用过量提醒 ────────────────────┐   │   │
│  │ │ 设备 [Looki L1 ▼] 提醒时限 [60 分钟 ▼] │   │   │
│  │ └──────────────────────────────────────┘   │   │

│  │ └──────────────────────────────────────┘   │   │
│  └────────────────────────────────────────────┘   │
│                                                    │
│  [取消] [创建]                          （创建模式） │
│  [取消] [保存] [删除心愿]                （编辑模式） │
```

**触发器卡片交互**：点击选中（蓝色描边），再次点击同一卡片取消选择。可以不选任何触发器，此时心愿不携带提醒。

### 3.3 心愿内触发器选择

- **切换选择**：点击触发器卡片选中（蓝色描边高亮），再次点击同一卡片取消选择。可以不选任何触发器。
- 三种预设类型（由中央目录定义，客户端从 `/api/trigger-types` 读取显示名和参数）：
  - `blacklist_usage_milestone`（黑名单使用过量提醒）：平台固定为全平台，不显示平台选择；仅选择提醒时限（分钟）
  - `device_usage_milestone`（设备使用过量提醒）：设备选择 + 提醒时限（分钟）
  - `late_usage_milestone`（使用过晚提醒）：设备固定为全部设备，不显示设备选择；仅选择起始时间和提醒时限（分钟）
- 提醒时限选项必须读取中央目录的 `interval_minutes.allowed_values`，当前为 15、30、60、120；不得使用客户端自造字段或仅显示 60 分钟的回退结果
- 每种触发器列表的条目模板使用中央目录定义的固定参数
- 不需要、也不允许用户增删触发器类型，全部由中央目录预置
- 不提供独立触发器对象的创建、修改、删除或管理页面
- 已有心愿允许修改同类型参数、关闭提醒或替换为另一中央预设类型
- “关闭提醒”写入 `enabled=false` 并保留实例；再次选择同类型时更新原实例并恢复 `enabled=true`
- 只有替换为不同类型时才由客户端内部删除旧实例并创建新实例
- 客户端在创建心愿成功后保存首次挂接；编辑模式分别保存文字和提醒变化，这些都是内部实现细节

### 3.4 按钮行为（创建模式）

- **创建**：校验文字（1-30字）→ 为本次提交生成并保留稳定 `request_id` 后 POST 心愿创建。若选择了触发器，再为挂接生成另一个稳定 `request_id` POST 触发器创建（含必填的 `config_version`、`interval_minutes` 和 `parameters`，其中 `interval_minutes` 从触发器参数中提取后从 `parameters` 中移除）。网络结果不确定时不得换新 ID 重复创建心愿。
- 挂接失败时提示“心愿已创建，但提醒设置失败”，刷新中央最终记录；用户可从卡片编辑入口重新设置提醒。
- **取消**（模板按钮）：关闭模板，不保存当前未提交修改；它不是"取消心愿"。

### 3.4b 按钮行为（编辑/删除模式）

- 编辑保存：文字变化使用心愿 PATCH；提醒变化使用触发器实例接口。只发送实际变化的部分。若发生部分成功，保持窗口并刷新中央最终状态，明确显示"文字已保存，提醒修改失败"或相反结果。
- 删除心愿：经过一次明确永久删除确认后调用中央 DELETE。成功后关闭模板并从当前列表移除。
- 取消：关闭模板，不保存当前未提交修改；它不是“取消心愿”。

### 3.5 编辑与删除边界

> **当前状态**：心愿编辑/删除与完结语义自 v1.12.0 接入，当前共享总契约为 v1.13.1。浏览器仍调用本地 PATCH/DELETE，本地代理转换为中央 POST 兼容入口；到期完结使用专用 POST 动作，旧 `/cancel` 只保留服务端兼容。

- 心愿文字和提醒可编辑；3/7 天周期控件只读灰置，固定日期不在模板中显示或编辑。
- 每日结果仍通过日期评估弹窗修改；这不属于编辑心愿基础信息。
- 不提供“取消心愿”或未到期提前归档；只在最后业务日结束后提供“完结心愿”。
- 删除不受当前状态、每日评估或提醒是否触发过的限制；中央负责清除心愿主体与生命周期事件，并保留但解除真实提醒事件的索引。

## 4. 事件时间线页

### 4.1 页面结构

目标页面结构如下：

```
┌────────────────────────────────────────────────┐
│  📋 事件时间线                                   │
│  2026年8月9日 · 心愿与事件记录                    │
├────────────────────────────────────────────────┤
│  ▾ 当前背景摘要                                  │
│  ▸ AI 理解说明                                   │
├────────────────────────────────────────────────┤
│  ▸ 事件与报告设置                                │
├────────────────────────────────────────────────┤
│  [心愿卡片区域]                                  │
│  （心愿卡片，按 2.2 布局）                        │
├────────────────────────────────────────────────┤
│  📜 今日时间线                                   │
│  ┌─────────────────────────────────────────┐  │
│  │ ⭐ 09:30 · 心愿提醒·设备使用               │  │
│  │ 📊 10:00 · 设备使用·书房电脑               │  │
│  │ ⚙️ 12:15 · Life Radio started             │  │
│  └─────────────────────────────────────────┘  │
└────────────────────────────────────────────────┘
```

### 4.2 现役边界

- 页面顶部显示当前心愿卡片。
- 页面下方只展示来自 `/api/timeline-events` 的真实中央事件。
- 不再保留旧 `timelineEvents` 模拟数组、旧时间线页面或独立自定义事件页面。
- 背景摘要是 `/api/event-background` 的动态只读视图，不是 AI 摘要，也不是时间线事件。
- 不在该页恢复旧 AI 摘要和旧四卡片统计。
- 现有页面代码可作为实现基线，但最终排版、字号和交互由本次独立前端任务统一调整；不得另建第二套页面或 mock 数据分支。

### 4.3 时间线事件条目格式

```
┌──────────────────────────────────────────────┐
│ HH:MM   [图标] [精简标题] [可选 ⭐]           │
│         [详情；达到 2小时15分钟 等时长标红]    │
└──────────────────────────────────────────────┘
```

- 事件必须比背景摘要更醒目：标题建议不小于 16px、粗体；详情建议不小于 14px；背景摘要继续使用较弱的正文层级。
- `importance=high`：橙色增强边框并显示 ⭐。
- `category=system` 且不是 high：灰色。
- 其他事件：统一蓝色。不要再按心愿、触发器、设备扩展更多卡片颜色。
- 图标只表达类型，不额外显示“心愿提醒”“系统里程碑”等文字标签。心愿提醒的标题本身以 `心愿提醒·` 开头。
- 标题保持精简。设备用量事件显示 `设备使用·<设备名>`，不得把“累计使用 240 分钟”塞进标题。
- 详情中的时长使用 `x小时y分钟`；整小时可写 `x小时`，不足一小时写 `y分钟`。匹配到的时长文字使用红色强调，但其余详情保持普通文字颜色。
- 设备用量详情由中央给出该设备应用和网站合并排序后的 Top 5；前端直接展示，不自行拆成“应用 Top 5 + 网站 Top 5”，也不重新做所有设备混合统计。
- `detail` 超长时可折叠，默认仍应看见首段核心结论。

### 4.4 当前背景摘要

- 数据源为 `GET /api/event-background?business_date=YYYY-MM-DD`。
- “当前状态”只展示 15 分钟内仍在线的设备。每台设备先显示“设备在线”，紧接着显示该设备仍新鲜的“正在使用”条目；不同设备不能拆成两个独立列表。
- 离线设备及其旧应用不显示。即使只读缓存来自旧版中央，前端也要过滤 `is_stale=true` 的 `device_online` 和 `current_app`。
- 位置与活动允许保留上次状态，并显示中央返回的更新时间。
- 活动状态必须显示中文：`stationary→静止`、`walking→步行`、`running→跑步`、`transport→乘坐交通工具`、`unknown→未知`。优先直接展示中央中文 `display_text`，禁止把原始英文枚举暴露给用户。
- AI 理解说明保持独立可折叠区域，不与当前状态混排。

目标示例：

```text
当前状态
联想小A在线。
联想小A正在使用 https://www.bilibili.com/video/…。
小米手机在线。
小米手机正在使用率土之滨。
当前位于重庆市 · 南岸区 · 广福大道。
上次活动状态为静止（上次更新：18:01）。
```

### 4.5 今日早报设置

今日早报不再使用“启用开关 + 触发方式下拉框”，改为两行可取消单选：

```text
○ 首次使用设备   延迟（分钟）[ 60 ]
○ 固定时间                    [ 09:00 🕰 ]
```

- 两项互斥，选中任意一项即表示 `morning_report.enabled=true`。
- 再次点击已经选中的一项，取消选择并保存为 `enabled=false`。
- 选“首次使用设备”时提交 `mode=after_first_usage`、整数 `delay_minutes`、`local_time=null`。
- 选“固定时间”时提交 `mode=fixed_time` 和合法 `HH:mm`；`delay_minutes` 仍保留中央所需合法值，但不在该模式下解释为触发条件。
- 离线缓存状态下整组设置只读，不得本地假保存。

### 4.6 查询窗口与业务日

中央时间线接口要求同时提供 `from`、`to`，二者必须是以 `Z` 结尾的 UTC ISO-8601 时间，且范围不得超过 24 小时。

WebUI 使用 `/api/settings` 返回的 `timezone=Asia/Shanghai` 和 `day_start_hour`，把当前选中的业务日换算为完整 24 小时 UTC 窗口，再请求：

```text
GET /api/timeline-events?from=<UTC-Z>&to=<UTC-Z>
```

页面标题和“今日”判断均使用同一业务日，不按浏览器自然日零点另算。首期只展示当前业务日，不增加跨日历史时间线浏览控件。

事件记录中的 `occurred_at` 是 UTC。条目时间必须通过 `Date`/`Intl.DateTimeFormat` 按共享 `timezone` 转为本地钟表时间；禁止直接截取 ISO 字符串的小时部分。

### 4.7 离线缓存状态

PC 本地代理在中央读取失败、返回最近一次持久只读缓存时，应增加响应头：

```text
X-Life-Radio-Cache: stale
```

WebUI 任一心愿、触发器目录/实例或时间线读取检测到该标记后：

- 在心愿区域显示“当前离线中”；
- 继续显示缓存内容；
- 禁用创建、编辑、删除心愿、每日评估和提醒写入；
- 不把写入失败伪装成成功。

恢复取得中央新响应后移除提示并恢复操作。该响应头是 UI 实施前的小型 PC 代理前置修改，不改变中央契约和 JSON 正文。

## 6. API 依赖

| 端点 | 用途 |
|------|------|
| `GET /api/wishes` | 获取当前心愿列表（限制 3 条） |
| `POST /api/wishes` | 创建心愿 |
| `PATCH /api/wishes/:id` | 仅修改心愿文字 |
| `DELETE /api/wishes/:id` | 永久删除心愿并执行中央关联清理 |
| `PUT /api/wishes/:id/days/:date` | 评估单日结果 |

## 9. 文本联调授权边界

本次前端任务允许顺带调整“中央生成、WebUI 展示、未来 AI 输入计划复用”的文本内容，目的是让用户看到的规范文字与未来发送给 AI 的文字保持同源。该授权只覆盖展示投影，不授权改变事实或计算结果。

### 9.1 可以修改

- `pc-dashboard/web/scripts/wishes-events.js`：文本排列、折叠、图标、时间显示以及对中央规范文字的原样展示。
- `pc-dashboard/web/styles/wishes-events.css` 和必要的 `dashboard.html`：纯视觉布局。
- `central-server/central/storage.py` 中 `event_background()` 及时间线读取时的**展示文字投影**：背景摘要、AI 理解说明、实时状态中文文案、旧事件的只读显示格式。
- `central-server/central/evaluator.py` 中写入时间线事件的 `title`、`detail` 文案，以及纯时长格式化函数；不得改变产生事件的条件和结构化证据。
- `central-server/central/report_text.py`：早报、晚报、定时总结的纯文本模板和排序后的表达方式；不得改变统计窗口或数据选择来源。
- 上述内容的直接测试和现役文档。

### 9.2 不能修改

- SQLite 表、字段、迁移、原始 `events`、既有长期记录或删除策略。
- API 路径、请求/响应字段、枚举、鉴权、设备凭据和 `contracts` 契约。
- 业务日、跨日时间、统计窗口、AFK 裁剪、Top 5 计算、黑名单匹配、去重键、里程碑阈值、调度时间和心愿有效期。
- `subject`、`evidence`、`importance`、`delivery` 的数据语义；不得为了排版伪造缺失事实。
- AI 提供方、真实投送、认证、重试和消费游标。

### 9.3 必须停下交总控审批的情况

- 目标文案需要新增字段或改变契约。
- 需要改变哪些事件被生成、筛选或发送给 AI。
- WebUI 与中央现有结构化证据发生矛盾，无法仅靠文字投影解决。
- 需要改写或删除已经存在的时间线事件。

前端 Agent 交付时必须把修改分成“纯前端视觉”和“中央规范文字”两组列出，便于总控分别验收。现役单 AI reader 被动读取已经完成真实 AI 配对与读取验收；这不代表旧主动投送链路已经实现，也不能把中央 `served` 状态解释为 AI 已阅读或理解。

## 10. v1.15.3 AI 读取管理补充

- AI 读取管理位于现有事件页面，个人模式只显示和维持一个有效 AI 连接；新 reader 成功配对时旧 Token 自动撤销。reader 名称来自当前有效配对身份；事件与报告设置中移除重复的 AI 名称行。Token 到期只显示月日，最近访问只显示最新一条的时间和事件数量。
- 每个普通/高优先级事件卡右侧使用中央返回的 `ai_reader.state`：`served` 显示橙底“已推送”，`not_served` 显示灰底“待推送”。所有低优先级事件不提供给 AI，也不显示标记。该状态由当前 reader 当前 epoch 的访问记录动态计算，不写入历史事件。
- “清理标记”只清理当前读取进度；历史访问日志保留。旧游标返回 `409`，AI skill 自动无游标重试并重新获取当前业务日。
- 配对文本只在按钮响应和剪贴板中短暂出现，不进入本地缓存、页面持久存储或日志；浏览器仍不能获得长期 AI Token 或中央设备 Token。
- “查看 Skill”只打开 PC 数据目录中的最新导出副本，不直接打开仓库原件。“查看发送原文”点击后立即打开弹窗并显示获取中，随后展示按最新已签发游标计算、始终含完整理解说明的 compact JSON；预览不推进游标、不清理标记、不写访问日志。
