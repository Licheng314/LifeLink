# 事件右下角系统提示-设计方案

> 状态：待实现
> 创建：2026-08-16
> 范围：`pc-dashboard/desktop_app.py`
> 关联：事件时间线、心愿与事件系统、久坐提醒

## 一、需求

1. 当中央服务产生新的 timeline 事件时，PC 客户端在 Windows 右下角弹出系统通知（balloon notification），让用户即使不看 WebUI 也能感知到重要事件发生。
2. 暂时禁用原本自带的"久坐提醒"右下角提示，避免两套通知互相干扰。
3. 久坐提醒的计时逻辑保留，只是不弹通知——未来可一行恢复。

## 二、现状梳理

### 2.1 PC 客户端架构

`desktop_app.py` 包含三个核心类：

| 类 | 位置 | 职责 |
|---|---|---|
| `UsageStatusWindow` | 254 行 | 用时状态悬浮窗（tkinter Toplevel），内含 `_fetch_snapshot` 后台线程拉 live-usage |
| `WindowsTrayIcon` | 829 行 | 系统托盘图标，`notify()` 方法（1018 行）封装 `Shell_NotifyIconW` balloon |
| `LifeRadioDesktopApp` | 1059 行 | 主应用，启动服务、托盘、状态窗口，含 `run()`（1277 行） |

### 2.2 现有后台线程模式

`_fetch_snapshot`（629 行）是现成的可参考模式：

```
后台线程（daemon）
  → HTTP 请求（self.opener.open，绕过系统代理直连 127.0.0.1:8090）
  → result_queue.put(result)
  → 主线程 poll_results（652 行，self.root.after(100, ...) 轮询 queue）
  → render(data)
```

**关键约束**：`Shell_NotifyIconW` 必须在 tkinter 主线程调用，不能在后台线程直接 `tray.notify`。新功能需照搬"后台线程拉数据 → queue → 主线程弹通知"的模式。

### 2.3 久坐提醒当前路径

```
UsageStatusWindow.update_sedentary_timer()（702 行，每秒执行）
  → sedentary_timer.advance() 返回 notify=True/False
  → if notify: self.notify_break("久坐提醒", ...)（719 行）
  → notify_break 在 LifeRadioDesktopApp.run() 中传入（1293 行）：
      notify_break=self.show_sedentary_notification
  → show_sedentary_notification（1173 行）：
      1. record_custom_event("sedentary.reminder_triggered", ...)
      2. self.tray.notify(title, message)（1189 行）
```

### 2.4 timeline 接口

中央服务接口：`GET /v1/timeline-events`

- 代理路径：PC 客户端通过本机代理 `GET /api/timeline-events` 转发（`sync_server.py` 2765 行）
- 参数：`from`/`to`（UTC ISO 时间，必填）、`importance`（可选，`low`/`normal`/`high`）
- 返回：`{"window": {...}, "events": [...]}`，事件按 `occurred_at DESC, timeline_event_id DESC` 排序
- 事件字段：

| 字段 | 说明 |
|---|---|
| `timeline_event_id` | UUID，唯一标识，可用于去重 |
| `occurred_at` | UTC ISO 时间字符串 |
| `event_key` | 如 `wish.created`、`report.morning`、`application.started` |
| `category` | `wish`/`trigger`/`device`/`user`/`system` |
| `importance` | `low`/`normal`/`high` |
| `title` | 事件标题（中文） |
| `detail` | 事件详情文本 |

### 2.5 事件量级统计（2026-08-16 实测，过去 12 小时）

| importance | 数量 | 典型 event_key |
|---|---|---|
| high | 9 | `wish.scheduled_reminder`、`system.device_usage_milestone` |
| normal | 19 | `report.morning`、`report.evening`、`wish.created`、`wish.result_revised` |
| low | 13 | `application.started`（每次 PC 客户端启动都会产生） |
| **合计** | **41** | 全量弹窗会刷屏 |

## 三、方案设计

### 3.1 用户确认的决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 通知范围 | 排除 low，弹 normal+high | 避免应用启动等低优先级事件刷屏 |
| 轮询频率 | 60 秒 | 通知延迟可接受，性能开销小 |
| 久坐提醒 | 保留计时，只禁通知 | 未来一行即可恢复 |
| 启动去重 | 从最新开始，不回溯 | 避免开机被历史事件刷屏 |

### 3.2 新增 `TimelineNotifier` 类

**位置**：`desktop_app.py`，`WindowsTrayIcon` 类之后、`LifeRadioDesktopApp` 类之前（约 1058 行）

**职责**：后台线程定期拉取 timeline，过滤、去重，将待通知事件放入 queue

**核心逻辑**：

```python
class TimelineNotifier:
    def __init__(self, opener, out_queue, stop_event):
        self.opener = opener          # build_opener(ProxyHandler({}))，绕过系统代理
        self.out_queue = out_queue    # queue.Queue，存放 (title, message)
        self.stop_event = stop_event  # threading.Event，优雅停止
        self.baseline = None          # 首次拉取记录的最新 occurred_at
        self.notified_ids = set()     # 已通知的 timeline_event_id（内存，重启清空）

    def run(self):
        # 首次：拉取最近事件，记录 baseline，不通知任何历史事件
        # 后续：每 60 秒拉取 occurred_at > baseline 的新事件
        #   过滤 importance == "low"
        #   去重 timeline_event_id
        #   对每条新事件：out_queue.put((title, detail_truncated))
        #   更新 baseline 为最新事件的 occurred_at
        while not self.stop_event.is_set():
            self._poll_once()
            self.stop_event.wait(TIMELINE_POLL_SECONDS)
```

**拉取 URL**：
```
/api/timeline-events?from=<baseline_utc_iso>&to=<now_utc_iso>
```

- `from` 设为 baseline（首次拉取时设为当前时间减 1 秒，确保能拉到当前最新事件）
- `to` 设为当前 UTC 时间
- 不传 `importance` 参数，前端过滤更灵活（中央接口的 importance 过滤是精确匹配，无法表达"排除 low"）

**过滤规则**：
```python
if event["importance"] == "low":
    continue
if event["timeline_event_id"] in self.notified_ids:
    continue
# 通过过滤 → 通知
```

**通知内容**：
- 标题：`event["title"]`（截断到 63 字符，`Shell_NotifyIconW` 的 `szInfoTitle` 上限）
- 正文：`event["detail"]`（截断到 255 字符，`szInfo` 上限），为空则用标题

### 3.3 主线程 poll notification queue

在 `LifeRadioDesktopApp` 中新增：

```python
# __init__ 中
self.notification_queue: queue.Queue[tuple[str, str]] = queue.Queue()
self.timeline_stop_event = threading.Event()
self.timeline_thread: threading.Thread | None = None

# run() 中，服务就绪后启动
self.timeline_thread = threading.Thread(
    target=TimelineNotifier(
        opener=self.http_opener,  # 复用已有的 build_opener(ProxyHandler({}))
        out_queue=self.notification_queue,
        stop_event=self.timeline_stop_event,
    ).run,
    daemon=True,
    name="life-radio-timeline-notifier",
)
self.timeline_thread.start()

# 主线程轮询 queue（类似 poll_results）
def poll_notifications(self):
    pending = []
    try:
        while True:
            pending.append(self.notification_queue.get_nowait())
    except queue.Empty:
        pass
    for title, message in pending:
        if self.tray is not None:
            self.tray.notify(title, message)
    self.notification_job = self.root.after(500, self.poll_notifications)
```

**轮询频率**：500ms 检查一次 queue（比 `_fetch_snapshot` 的 100ms 宽松，因为事件通知不需要那么及时）

### 4.3 TimelineNotifier 完整伪代码

```python
class TimelineNotifier:
    def __init__(self, opener, out_queue, stop_event):
        self.opener = opener
        self.out_queue = out_queue
        self.stop_event = stop_event
        self.baseline = None
        self.notified_ids: set[str] = set()

    def run(self):
        # 首次拉取：建立 baseline，不通知
        self._establish_baseline()
        # 后续轮询
        while not self.stop_event.is_set():
            self.stop_event.wait(TIMELINE_POLL_SECONDS)
            if self.stop_event.is_set():
                break
            self._poll_new_events()

    def _establish_baseline(self):
        now_utc = datetime.now(timezone.utc)
        from_iso = (now_utc - timedelta(seconds=1)).strftime("%Y-%m-%dT%H:%M:%SZ")
        to_iso = now_utc.strftime("%Y-%m-%dT%H:%M:%SZ")
        events = self._fetch(from_iso, to_iso)
        if events:
            self.baseline = events[0]["occurred_at"]  # 最新事件时间
            for e in events:
                self.notified_ids.add(e["timeline_event_id"])
        else:
            self.baseline = to_iso

    def _poll_new_events(self):
        now_utc = datetime.now(timezone.utc)
        to_iso = now_utc.strftime("%Y-%m-%dT%H:%M:%SZ")
        events = self._fetch(self.baseline, to_iso)
        if not events:
            return
        new_events = []
        for e in reversed(events):  # 从旧到新
            if e["timeline_event_id"] in self.notified_ids:
                continue
            if e["importance"] == "low":
                self.notified_ids.add(e["timeline_event_id"])
                continue
            new_events.append(e)
            self.notified_ids.add(e["timeline_event_id"])
        for e in new_events:
            title = str(e.get("title") or "事件通知")[:63]
            detail = str(e.get("detail") or "")[:255]
            self.out_queue.put((title, detail))
        self.baseline = events[0]["occurred_at"]  # 更新为最新

    def _fetch(self, from_iso, to_iso):
        url = f"{TIMELINE_URL}?from={from_iso}&to={to_iso}"
        try:
            with self.opener.open(url, timeout=10) as response:
                payload = json.loads(response.read().decode("utf-8"))
            return payload.get("events", []) if isinstance(payload, dict) else []
        except Exception as error:
            logging.warning("Timeline 事件拉取失败: %s", error)
            return []
```

## 五、风险与注意事项

### 5.1 线程安全

- `Shell_NotifyIconW` 必须在主线程调用，**禁止**在 `TimelineNotifier` 后台线程直接调 `tray.notify`
- 必须通过 queue → 主线程 `poll_notifications` → `tray.notify` 的路径
- `notified_ids` 集合只在后台线程读写，无需加锁

### 5.2 通知频率控制

- 60 秒轮询一次，但一次轮询可能拉到多条新事件
- 如果一次 put 多条通知到 queue，主线程会连续弹多个 balloon
- Windows balloon 通知本身有排队机制（前一条显示完才显示下一条），但仍可能造成通知堆积
- **可选增强**：如果一次拉到超过 3 条，合并为一条"有 N 条新事件，最新：xxx"的通知。初版暂不实现。

### 5.3 时间戳格式

- 中央接口要求 `from`/`to` 为 UTC ISO 格式
- `occurred_at` 返回的也是 UTC ISO 字符串
- baseline 用字符串比较即可（ISO 8601 格式天然可排序）
- 注意：`datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")` 不含毫秒，中央服务返回的 `occurred_at` 可能含毫秒，字符串比较时需确认一致性

### 5.4 启动时序

- `TimelineNotifier` 在 `run()` 中服务就绪后启动
- 如果中央服务不可达，`_fetch` 返回空列表，baseline 会被设为当前时间，不影响后续轮询
- 如果长时间不可达，`notified_ids` 不会增长，恢复后可能一次性弹多条通知——可接受

### 5.5 内存占用

- `notified_ids` 集合只增不减，长期运行会持续增长
- 41 个事件/12 小时 ≈ 82 个/天 ≈ 60000 个/2 年
- 每个 UUID 字符串约 36 字节，60000 个 ≈ 2MB，可接受
- **可选增强**：定期清理超过 7 天的 id。初版暂不实现。

### 5.6 久坐提醒禁用后的影响

- `show_sedentary_notification` 不再被调用，其中的 `record_custom_event("sedentary.reminder_triggered", ...)` 也会被跳过
- 中央服务不再收到久坐提醒事件——如果需要保留事件记录但不弹通知，可改为：

```python
def _sedentary_notify_silent(self, title, message):
    self.record_custom_event("sedentary.reminder_triggered", title, message, {...})
    # 不调 tray.notify

# 1293 行
self.root, notify_break=self._sedentary_notify_silent,
```

**决策待定**：是否保留久坐事件的中央记录。初版方案是直接 noop，不记录事件。
