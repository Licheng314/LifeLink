# 手机端中央同步

1. 在中央服务生成统一的 `dashboard` 范围单行 `LR1.` 邀请码；`upload` 只保留旧协议兼容，不再作为新手机的推荐入口。
2. 手机打开「设置 → 中央服务」，粘贴设备配对码并点「检查配对码」。
3. 核对中央 HTTPS 地址、权限、有效期和本机名，然后确认绑定。
4. 授予「使用情况访问」后会采集并上传 `app.foreground`；开启位置采集并授予位置权限后会上传原始 `location.observation`，以及按 150 米半径聚合的 `location.sample` / `location.stay`。

邀请码只在领取期间保留于内存；长期设备凭据由 Android Keystore 加密保存。绑定成功后应用调用该中央地址的 `/v1/events/batches` 上传事实，并通过 `GET /v1/settings/shared` 读取共享跨日设置。设置读取使用现有同步节奏，失败时保留最近有效只读缓存，不影响上传 ACK、退避或认证状态；手机设置页只读显示跨日时间，不提供修改入口。

每批上传最多 500 条。只有响应 `confirmed_event_ids` 明确确认的事件 revision 才会标记送达；限流、网络和服务端临时错误会保留队列并退避重试。手机上的同步间隔仍是本机运行参数，不属于中央共享设置。

手机不再每 15 秒通过公网轮询 `/v1/health`。连接状态由经过设备 Token 验证的共享设置读取和真实同步结果更新；匿名健康检查只属于首次绑定或人工诊断。15 秒界面循环只刷新本机位置与缓存状态，不产生公网请求。

Android v3.8 起，总览页通过已注册设备凭据读取和修改中央心愿，并提供往期心愿与事件时间线。事件页按 `Asia/Shanghai` 和中央共享的 `day_start_hour` 划分业务日，显示当前业务日“今天”和前一业务日“昨天”，今天在前、昨天在后；这只是 Android 展示范围，不改变中央时间线语义。当前源码已接入 v1.13.1：创建与编辑复用同一模板，编辑只修改文字并灰置 3/7 天周期；进行中心愿可调整提醒，最后业务日结束且每日结果已填后可手动完结，归档或旧取消心愿只可改文字或永久删除。心愿和触发器的更新/删除默认使用中央 POST 兼容入口，避免公网 HTTPS 映射阻断 PATCH/DELETE。删除成功后先清理本机只读缓存，再刷新中央。断网时缓存只读，不能形成手机端权威。

Android v3.9 起读取中央触发器类型目录与实例列表。用户只能在心愿创建或该心愿卡片内挂接、替换或解除一个中央预设触发器；手机端不提供独立触发器管理页，也不允许创建新的触发器形式。v3.10 起黑名单用量固定汇总全平台，晚间使用固定观察全部设备，两者均不显示范围选择。周期只能选择中央目录公布的值，晚间提醒使用 `HH:mm` 本地时间；触发器目录或实例处于离线缓存状态时只读。若中央已存在同一心愿的多个触发器，手机不会擅自选择其中一条或继续写入，而是提示先处理冲突。

活动位置段会以同一 event ID 和递增 revision 持续更新。离开 150 米范围或主动停止位置服务时，该段会用更高 revision 定稿，因此已确认过的活动版本仍会再次进入上传队列。

手机将事件列表作为独立入口读取中央时间线，不在本机重新计算系统里程碑；每条事件按既有类别和事件键显示对应的 Lucide 风格图标。往期心愿页面只展示归档心愿。首个成功的后台事件轮询只建立本机提醒基线；之后若中央出现尚未提醒过的 `importance=high` 或 `importance=normal` 事件，手机会通过“事件提醒”系统通知渠道提醒一次，`low` 事件不通知。时间线始终按 `Asia/Shanghai` 显示，离线时只展示最近成功读取的缓存并标明“当前离线中”，不可写回中央。手机端不再提供事件、早晚报或定时总结的设置入口；`scheduled_reminder` 仍只允许作为一条心愿的提醒，客户端不显示无意义的间隔设置。

Android v3.15 起，手机界面采用与 WebUI 一致的“暖沙青”视觉语言，但不追求功能对齐。事件、心愿、数据和设置保持四个清晰入口：数据页只展示采集与中央派生结果，所有会改变采集行为的权限和开关统一放在设置页。中央服务的重新绑定与设备 ID 默认折叠，同步频率改用明确的常用档位，避免在普通设置中暴露不必要的诊断细节。
